# Phase 2 · Intermediate Python & Software Engineering

**Goal:** write professional Python (object-oriented, idiomatic, typed and tested), solve interview-style algorithm problems, and work like an engineer (environments, testing, linting, Git workflows, CI).
**Modules:** M07–M10 · 34 lessons · ~54.5 h · **Portfolio project P2:** `textkit`, a tested, typed package with CI (`spec/09`) · **Phase exam `p2-exam`:** 25 questions + 3 coding problems (one per DSA pattern family), 100 minutes, `ai_policy: none`.

**Phase teaching notes**
* Type hints and docstrings are now required in all starters and solutions.
* M09 uses **relative speed tests** (`assert_fast_enough`, `spec/05` §4.6) wherever complexity matters. Choose input sizes where the naive approach is at least 100× slower, and keep the naive approach under 10 s on a laptop (`assert_fast_enough` compares against the reference on the learner's own machine).
* Tree and linked-list exercises get `ListNode`/`TreeNode` classes and `build_list`/`build_tree` helpers in `setup`, so learners focus on the algorithm.
* M10 mixes pytest-graded exercises (testing, typing, refactoring, logging) with workflow tasks (uv, ruff, pre-commit, GitHub Actions) that are checked by the P2 project rubric.

## M07 · Object-Oriented Programming
`m07-oop` · 8 lessons · ~12 h · Needs M06

**Why it matters at work:** libraries such as scikit-learn, PyTorch and FastAPI are designed with classes. Reading and extending them needs fluent OOP, and so do system-design conversations.

**Outcomes:** design classes with clear responsibilities and invariants; use properties, inheritance, composition and protocols; implement dunder methods for natural syntax; use dataclasses and enums; follow the scikit-learn estimator conventions.

Set up your computer

You will run every example and exercise of this course on your own computer, exactly as you will at work. This takes about 30 minutes, once.

What you will install

  • Python 3.15: the course is checked with it, and lessons use its new features (lazy imports, frozendict, sentinel, unpacking in comprehensions). Older versions run most of the code but not all of it.
  • An editor: Visual Studio Code with the Python extension is a good free choice; PyCharm, Zed or any editor you like also work.
  • pytest and the course's other code-quality tools: pytest checks your exercise solutions. Data, machine-learning and deep-learning libraries come later, one file per phase (step 6).

  2. Open the starter file in your editor and write your solution.
  3. In the terminal, go into the folder and run the tests for that exercise:
  4. Read the first failure: pytest shows the line that failed and the values it compared. Fix, save, run again.
  5. When a whole test file passes, pytest prints a completion code such as 5F2A-91C3. Paste it into the exercise on the lesson page to record it as passed.

Run plain pytest (no file name) to check every exercise in the pack at once; add -x to stop at the first failure.

For example, at the start of Phase 3:

On Linux, the standard PyTorch package also downloads NVIDIA's CUDA libraries, about 4 GB. Every graded exercise runs on the CPU, so without an NVIDIA graphics card, first install PyTorch with the CPU-only command from pytorch.org, then install requirements-deep-learning.txt.

Every pinned library installs from ready-made packages (wheels) on Windows 10 or 11 (x64), on macOS 15 or later with Apple silicon, and on Linux with glibc 2.39 or later, such as Ubuntu 24.04. The exceptions:

  • Windows: FAISS (Phase 5) has no Windows packages. requirements-deep-learning.txt skips it there, and the FAISS part of lesson M23-L05 runs in WSL 2.
  • Intel Macs: PyTorch (Phase 5) has no packages for them. Use a Linux virtual machine or another computer for Phase 5.
  • Older Linux: pip has to build orjson, which Gradio needs in Phase 6, from source with the Rust compiler. A newer distribution, or WSL 2 with Ubuntu 24.04, avoids that.

PySpark (elective E4) also needs Java 17 or later. Start it from the activated environment: its worker processes run the python3 on your PATH, and a different Python version stops them with PYTHON_VERSION_MISMATCH.

Libraries you try outside the course may not support Python 3.15 yet (pip finds no matching version, or starts compiling C code). Give that experiment its own virtual environment with an older Python, for example uv venv --python 3.14, rather than changing the course environment.

Notebooks and GPUs (later in the course)

Data-science lessons use Jupyter notebooks for exploration. Run them locally with python -m jupyter lab after installing requirements-core.txt, or open the .ipynb file in VS Code.

Every graded exercise runs on an ordinary laptop CPU. A few optional deep-learning experiments train faster on a GPU; if you don't have one, any hosted notebook service you choose will run the same notebook files.

Troubleshooting

Common problems and fixes
You seeFix
python: command not found or 'python' is not recognizedUse python3 (macOS, Linux) or py (Windows), and set the matching option in Settings. Open a new terminal after installing.
Windows opens the Microsoft Store when you type pythonInstall the Python install manager (step 1), or turn off the "App execution aliases" for python in Windows settings.
pytest: command not foundRun it through Python: python -m pytest. Check the virtual environment is active.
ModuleNotFoundError: No module named 'e1_word_freq'Run pytest from inside the pack folder, and keep the starter file's name unchanged.
ModuleNotFoundError: No module named 'pandas' (or another library)Activate the virtual environment, then install the requirements file of that phase (step 6), for example python -m pip install -r requirements-core.txt.
No matching distribution found, or pip starts compiling a libraryCheck that python --version shows 3.15 inside the active virtual environment. The course's files only list libraries that install on 3.15; for other libraries, see the tip in step 6.
VS Code runs a different PythonPress Ctrl+Shift+P, choose "Python: Select Interpreter" and pick the one in .venv.
Your output differs slightly from the pageCheck your Python and library versions; outputs on the pages come from the versions in the requirements files (step 6). Random numbers and timings differ on purpose and are labelled "Sample output".
